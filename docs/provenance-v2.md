# Provenance v2

Provenance v2 is an additive evidence layer over Archive Foundation v1.

## Why it is additive

Foundation v1 remains the migration compatibility layer:

- `SourceRecord` preserves the exact migrated source capture;
- `ProvenanceAssertion` preserves the original record-to-source assertion;
- legacy verification statuses are unchanged.

Provenance v2 adds normalized bibliographic identities and richer review fields
without claiming that missing metadata is evidence of falsity.

## Normalized bibliographic sources

A `BibliographicSource` represents an exact normalized source identity.

Normalization merges only captures whose complete migrated bibliographic payload
matches:

- citation;
- detail;
- URL;
- legacy source kind.

Every normalized source keeps `captureIds`, so the original migration captures
remain traceable.

The source type is conservative classification metadata:

- `book`
- `article`
- `website`
- `archive`
- `community`
- `unclassified`

It does not assert that a source is authoritative.

## ProvenanceAssertionV2

Each migrated v1 provenance assertion receives a corresponding v2 assertion.

The v2 assertion contains:

- canonical record ID;
- normalized bibliographic source ID;
- verification status;
- evidence role;
- optional claim ID;
- optional locator;
- optional checked-at timestamp;
- optional reviewer;
- optional editorial note;
- original source capture IDs.

The migration deliberately leaves review fields empty when the existing dataset
does not contain explicit review metadata.

## Editorial rules

1. Never upgrade verification status because a URL exists.
2. Never invent page numbers, sections, quotations, or reviewers.
3. Use claim-level evidence only when a specific claim can be identified.
4. Use locators only when the source provides a reliable locator.
5. Treat live URL availability as source-health information, not truth.
6. Preserve disputed and needs-review states.
7. Keep live web checks outside the build-critical validation path.

## Local audit report

Run:

`bun run archive:provenance-report`

The report measures structural coverage and editorial metadata gaps. It does
not contact external websites.

## Future work

The next editorial pass can populate:

- claim IDs;
- page/section/paragraph locators;
- checked dates;
- reviewer identity;
- source-health observations.

Those changes should be made from explicit source review, not generated by
migration code.
