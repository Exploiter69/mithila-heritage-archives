# Browser, Accessibility, and Performance Audit\n\nThis project now runs a real Chromium audit in CI against the Vite development server.\n\n## Coverage\n\nThe audit visits every primary public route at two browser viewport profiles:\n- Desktop: 1366×768\n- Mobile: 390×844\n\nFor each route it checks:\n- document language\n- canonical main#main-content\n- skip link\n- image alternative text\n- accessible names for buttons and ARIA buttons\n- accessible labels for form controls\n- duplicate IDs\n- Chrome accessibility-tree unnamed interactive controls\n- uncaught JavaScript errors and unhandled promise rejections\n- Largest Contentful Paint (LCP)\n- Cumulative Layout Shift (CLS)\n- Interaction to Next Paint (INP), when the browser reports an interaction entry\n- navigation timing / TTFB\n- total resource transfer size\n\nThe CI audit uses Chrome DevTools Protocol, including the Accessibility and Page/Runtime domains. It is therefore a browser-rendered audit rather than an HTML-only test.\n\n## Thresholds\n\nThe CI gate currently treats these as failures:\n- LCP > 4 seconds\n- CLS > 0.25\n- any browser runtime error\n- missing accessible names/labels\n- missing image alt text\n- duplicate IDs\n- missing language/main/skip-link foundations\n\nINP is recorded when available but is not failed when no qualifying interaction entry is produced; a route with no qualifying interaction cannot honestly be assigned an INP value.\n\n## Important scope\n\nThis is a repeatable Chromium audit, not a substitute for testing every physical device, browser engine, assistive technology, or network condition. Firefox/WebKit, VoiceOver/NVDA/TalkBack, real cellular networks, and real-user field data still require environment-specific validation.\n\n## Performance budgets\n\nClient build output also has deterministic budgets:\n- largest client JS asset: 450 KiB\n- largest client CSS asset: 120 KiB\n\nThese budgets prevent bundle regressions but do not replace CWV measurement.
